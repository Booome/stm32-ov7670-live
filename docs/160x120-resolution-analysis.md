# 分辨率选型分析：160x120 vs 160x128

## 背景

- LCD 物理分辨率 160x128（ST7735 1.8"，MADCTL MV=1 横屏）。
- 最初摄像头输出 160x128，意图填满 LCD。
- 实测对比发现：160x128 噪点明显多于 160x120，且左右边缘有杂色带
  （colorbar 测试和真实画面都复现）。
- 160x120 分支实测：噪点少、左边杂色带消失，右边仍有一条蓝色带但整体更干净。

## 根因：OV7670 两级缩放架构行为不同

OV7670 的 Image Scaler 由两级组成，二者对噪声的处理完全不同：

1. **DCW（Down Sampling，降采样）**：做**像素平均**。datasheet
   `SCALING_DCWCTR (0x72)` 的 bit[7]/bit[3] 名为 "average calculation
   option"，truncation/rounding 只是平均值的舍入方式。平均 N 个像素，噪声
   幅度降为原来的 1/√N（信噪比提升 √N 倍）。

2. **Digital Zoom（XSC/YSC，0x5x~1.0x 缩小）**：只有 "scale factor"
   （bit[6:0]），**没有 average 选项**——它只做抽取/插值，不平均、不降噪。
   非整数缩放因子（如 0.533x）还会产生非均匀抽取，引入混叠（aliasing），
   表现为边缘伪彩。

## 两个版本的信噪比对比

| | 160x120 | 160x128 |
|---|---|---|
| 缩放链路 | DCW **by4** | DCW **by2** + XSC 0.5x + YSC 0.533x |
| 每个输出像素平均的原始像素数 | 4×4 = **16** | 2×2 = **4**（zoom 再抽取，不平均）|
| 信噪比提升 | √16 = **4x** | √4 = **2x** |

因此 160x128 的噪点约为 160x120 的 2 倍。

## 为什么 160x128 无法根本解决

垂直方向从 VGA 480 行到目标行数的缩放路径受限于：

- DCW 只支持 by2 / by4 / by8 整数降采样。
- Digital Zoom 只支持 0.5x~1.0x 的**缩小**（不支持放大）。

```
480 -> 128 : 只能 DCW by2 (240) -> YSC 0.533x (128)   <- 非整数，必然混叠
480 -> 120 : DCW by4 (120)，整数路径，全程平均        <- 最优
```

没有组合能既填满 128 行又走整数降采样：`DCW by4` 只能到 120，而 Digital
Zoom 无法把 120 放大到 128。因此 160x128 的噪点与混叠是**结构性的**，
改寄存器无法根治。

## 缓解措施（有限，非根治）

1. **DCWCTR rounding**（bit[7]/[6]/[3]/[2] = 1）：只改变平均值的舍入方式
   （截断 vs 四舍五入），差异 ≤1 LSB，对随机噪点几乎无感。
2. **DSP 噪声抑制**（DNSTH `0x4C`、REG76 `0x76`）：能压一点噪点，但牺牲
   细节，且达不到物理平均的降噪效果。

以上措施最多把信噪比从 √4 略作提升，到不了 √16。

## 结论

160x120 是 OV7670 在 160 宽附近的硬件最优分辨率：DCW by4 整数降采样 + 全程
像素平均，信噪比最优、无混叠。采用方案：

- 摄像头输出 160x120（`COM3=0x04`、`DCWCTR=0x22`、`XSC/YSC=0x20`）。
- LCD 160x128 上居中显示，`PIPELINE_CROP_*` 宏裁切边缘（默认 TOP=1, LEFT=6, RIGHT=1），`PIPELINE_LCD_X/Y_OFFSET` 自动计算居中坐标。
- 清屏（`LCD_FillScreen`）保证黑边干净。

160x128 保留在 `160x128-backup` 分支，仅作对照参考。
